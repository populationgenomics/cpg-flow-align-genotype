# CRAM Repair — Usage

Repairing a sequencing group is a two step process, and there are three invocations below:
one for each repair type, and one for the reset.

**Step 1 — repair.** Pick the repair type that matches the defect. The script archives the bad
CRAM to `bad_cram/`, then cleans and realigns the reads and writes the corrected CRAM to the
output path you give it.

The archive is recorded by patching the meta of the **existing** `cram` analysis — the one that
already describes the CRAM being archived. No new analysis entry is created, and this is not
optional. Metamist meta updates merge, so nothing already on the record is lost:

```
repair_type:                      strip-qnames | trim-adapters
old_contaminated_cram_path:       gs://cpg-DATASET-<ns>/bad_cram/CPG123.cram
old_contaminated_cram_index_path: gs://cpg-DATASET-<ns>/bad_cram/CPG123.cram.crai
repair_script_used:               src/align_genotype/scripts/repair_scripts/<script>.py
repair_date:                      2026-09-28
```

The script locates that analysis by matching `--sg-id` against the active `cram` analysis whose
output is `--cram-path`. If there isn't one it fails rather than silently skipping, so the
archive never ends up unrecorded.

**Step 2 — reset.** The old CRAM has children: a gVCF, QC metrics, somalier fingerprints, SV
evidence, mito CRAMs. All of them were derived from the bad data. The reset script backs them
up alongside the archived CRAM and inactivates their metamist analyses, so the pipeline stops
reading them.

Add `--dry-run` to any of the three to see exactly what it would do without changing anything.

## Step 1 — Repair

### Strip QNAME suffixes

For CRAMs whose read names end in `/1` and `/2`. Those suffixes, left by older sequencers,
break mate pairing in `samtools fastq` when reads are not collated.

```bash
analysis-runner --skip-repo-checkout \
    --image australia-southeast1-docker.pkg.dev/cpg-common/images/cpg-flow-align-genotype:0.6.0 \
    --config src/align_genotype/scripts/repair_scripts/repair_config.toml \
    --dataset DATASET \
    --access-level test \
    --description 'strip qnames CPG123' \
    --output-dir "repair/strip-qnames" \
    python -m align_genotype.scripts.repair_scripts.strip_qnames \
        --cram-path gs://cpg-DATASET-test/cram/CPG123.cram \
        --output-path gs://cpg-DATASET-test/cram_repaired/CPG123.cram \
        --sg-id CPG123
```

### Trim adapters

For CRAMs aligned without removing adapters, which leaves spurious soft-clipping. Extracts the
reads back to FASTQ, trims adapters and poly-G with fastp, then realigns with DRAGMAP using the
same pipeline as production: DRAGMAP → dupblaster → coordinate sort → CRAM v3.0.

```bash
analysis-runner --skip-repo-checkout \
    --image australia-southeast1-docker.pkg.dev/cpg-common/images/cpg-flow-align-genotype:0.6.0 \
    --config src/align_genotype/scripts/repair_scripts/repair_config.toml \
    --dataset DATASET \
    --access-level test \
    --description 'trim adapters CPG123' \
    --output-dir "repair/trim-adapters" \
    python -m align_genotype.scripts.repair_scripts.trim_adapters \
        --cram-path gs://cpg-DATASET-test/cram/CPG123.cram \
        --output-path gs://cpg-DATASET-test/cram_repaired/CPG123.cram \
        --sg-id CPG123
```

## Step 2 — Reset the derived analyses

```bash
analysis-runner --skip-repo-checkout \
    --image australia-southeast1-docker.pkg.dev/cpg-common/images/cpg-flow-align-genotype:0.6.0 \
    --config src/align_genotype/scripts/repair_scripts/repair_config.toml \
    --dataset DATASET \
    --access-level test \
    --description 'reset CPG123' \
    --output-dir "repair/sg-reset" \
    python -m align_genotype.scripts.repair_scripts.sg_reset \
        --sg-id CPG123 \
        --dest gs://cpg-DATASET-test/bad_cram
```

Two things it deliberately leaves alone:

- **`cram` analyses.** Swapping the CRAM a sequencing group points at is the consequential
  step, so it is done by hand. Inactivating one without a registered replacement makes the
  pipeline realign from scratch.
- **Cohort-level analyses** — joint calls, matrixtables, ES indexes. Their outputs are shared
  with hundreds of other sequencing groups, so archiving or inactivating them would affect
  other samples. Those get regenerated by re-running the workflow, not by this script.
  `--include-multi-sample` overrides this if you really mean it.

The sequencing group entry itself is never touched.

---


```toml
[workflow]
only_sgs = ['CPG123']
force_stages = ['GenotypeWithGatk', 'CramQcSomalier', 'RunGvcfQc']
```

`only_sgs` matters — `force_stages` applies to every target in the cohort, so without it you
force-regenotype every sample in the cohort.

## Other scripts in this folder

| script | what it does |
| --- | --- |
| `reheader_cram.py` | Rewrites `@RG` ID/SM to a different sequencing group, for promoting a repair done under a test SG to its main counterpart. Regenerates the index. |
| `rewrite_crams.py` | Rewrites CRAM v3.1 to v3.0. Note it overwrites the original in place. |
| `alignment_recovery.py` | Rescues a failed alignment merge from per-shard BAMs still in batch-tmp. |
| `picard_fixprim.py` | Fixes duplicate primary alignments in a BAM. |

Each takes `--help`.
